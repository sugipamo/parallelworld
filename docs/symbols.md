# 記号と既存概念への対応

`docs/spec.md` と実装が実際にやっていることを記号で書き、数学の既存概念に対応させる。
厳密さは問わない。各対応に「一致」（定義がそのまま当てはまる）か「類比」（形が似ているだけ）を付けた。

コードはこの対応どおりに分けてある。

| 層 | 既存概念 | ファイル |
|----|----------|----------|
| 形式層 | リンデンバウム代数、ハイパードクトリンのファイバー、合同閉包 | `pw/lindenbaum.py` |
| 確率層 | ストーン空間、クレーダル集合、一般化ベイズ則、コピュラ | `pw/credal.py` |
| 接続 | 信頼性モデル、フレシェ＝ニコディム距離 | `pw/kernel.py` |
| 検証 | Γ のもとでの証明可能性 | `pw/lean_gate.py` |

## 2. 形式層 ― リンデンバウム代数（一致）

Lean命題を証明可能な同値で割ったものがリンデンバウム＝タルスキ代数。

```
𝓛_Γ = Prop / ~_Γ        F₁ ~_Γ F₂  ⇔  Γ ⊢ F₁ ↔ F₂
```

`Classical.choice` を許しているのでブール代数になる（許さなければハイティング代数）。`prove` の5種類は、この代数の中の関係にそのまま対応する。

| `prove` | 𝓛_Γ での意味 |
|---------|-------------|
| `iff` F₁ F₂ | [F₁] = [F₂] |
| `implies` F₁ F₂ | [F₁] ≤ [F₂] |
| `contradiction` F₁ F₂ | [F₁] ∧ [F₂] = ⊥ |
| `holds` F | [F] = ⊤ |
| `not` F | [F] = ⊥ |

システムが知っているのは 𝓛_Γ 全体ではなく、Π が与える関係だけ。つまり持っているのは「生成元と関係 Π で表示されたブール代数」𝔹_Π で、真の代数へは全射がある。

```
𝔹_Π ↠ 𝔹_Π′ ↠ ⋯ ↠ ⟨ℱ⟩ ⊆ 𝓛_Γ        （Π ⊆ Π′）
```

証明を追加することは、この商の列を一段進めること。

### 述語のファイバーと代入（一致）

閉じた命題だけでは同一性が語れない。定理はすべて ⊤ に潰れるので、証明済みの F₁, F₂ は必ず [F₁] = [F₂] になる（最初の実走で起きた）。潰れないのは述語の代数、つまり文脈 x : A の上のリンデンバウム代数 𝓛_Γ(x : A)（ローヴェアのハイパードクトリンのファイバー）。

主張は「対象 a が仕様 P を満たす」に分ける。

```
H  ⇝  (P, a)        P ∈ 𝓛_Γ(x : A),  a : A,  F = P(a)
```

代入 a* : 𝓛_Γ(x : A) → 𝓛_Γ、P ↦ P(a) はブール準同型なので、述語の間の関係は命題に降りる。

| `prove` | 意味 | 命題への帰結 |
|---------|------|--------------|
| `pred_iff` P₁ P₂ | [P₁] = [P₂]（同じ仕様） | a₁ = a₂ なら [P₁(a₁)] = [P₂(a₂)] |
| `pred_implies` P₁ P₂ | [P₁] ≤ [P₂]（詳細化） | [P₁(a)] ≤ [P₂(a)] |
| `obj_eq` a₁ a₂ | Γ ⊢ a₁ = a₂（同じ対象） | [P(a₁)] = [P(a₂)] |
| `pred_disjoint` P₁ P₂ | [P₁] ∧ [P₂] = ⊥（両立しない仕様） | [P₁(a)] ∧ [P₂(a)] = ⊥。同じコードについての形式的な主張なら ¬(H₁ ∧ H₂) |

等式の伝播は**合同閉包**（SMTソルバやe-graphと同じ）。「同じ知識」は「同じ仕様」かつ「同じ対象」で、どちらか一方だけを言うこともできる。

## 3. 可能世界 ― ストーン双対（一致）

ブール代数 𝔹 の点（2への準同型、超フィルター）が可能世界。有限なので単に 𝔹 のアトム。

```
Ω_Π = Hom(𝔹_Π, 2)
```

商 𝔹_Π ↠ 𝔹_Π′ は双対側で包含 Ω_Π′ ⊆ Ω_Π になる。v0.2 で「証明は Ω の絞り込みであってベイズ更新ではない」としたのはこの形。

| 状態変化 | 代数側 | 世界側 |
|----------|--------|--------|
| 証明の追加 | 𝔹 を商で割る | Ω を部分集合に縮める |
| 証拠の観測 | 何も変わらない | Ω 上の測度を重み付けし直す |

証明されていない定理に確率を置けること（論理的全知を仮定しないこと）は、𝔹_Π が 𝓛_Γ より粗いことに対応する。

## 4. 確率 ― 確率論理と不精確確率（一致）

v0.1 §3 の ⟦H⟧_E = Σ_{w⊨H} μ_E(w) は、文に確率を与える標準的な定義（ガイフマン、ニルソンの確率論理）。

v0.2 は μ を一つに決めず、線形制約を満たす μ の凸集合 𝒦 を状態とする。これは**クレーダル集合**（リーヴァイ、ウォーリーの不精確確率）で、`infer` は下側確率・上側確率。

```
P̲(φ) = min_{μ ∈ 𝒦∣E} μ(⟦φ⟧)        P̄(φ) = 1 − P̲(¬φ)
```

「いくつかの事象の確率が与えられたとき、別の事象の整合的な確率は区間になり、線形計画で求まる」はデ・フィネッティの確率の基本定理（ブール、ハイルペリン）。`infer` はこれをそのまま解いている。

v0.1 §6 の max(0, a + b − 1) はフレシェ不等式で、この定理の最小の例。

## 5. 接続仮説 ― 情報源の信頼性モデル（一致）

主張 H を命題 F = P(a) に結ぶ仮説は二つある。

```
g : 述語 P は、主張が言っている性質を表す          （仕様の仮説。主張ごと）
m : 対象 a は、コード s を表す                      （モデルの仮説。(s, a) ごとに一つ）
```

m は主張に属さない。同じコードと同じ対象に寄りかかる主張すべてが、同じ m を共有する。両方が成り立つとき、その接続は「信頼できる」。世界に課す制約は一つ。

```
r = g ∧ m        ⟦r⟧ ⊆ ⟦H ↔ F⟧
```

閉じた命題への接続（`ground`）は g だけを持ち、r = g。

**形式的な主張では g がない（一致）。** g が要るのは主張が自然言語の文だからで、これは検証（verification）ではなく**妥当性確認**（validation）の問題にあたる。片側が形式的でないので、検査で埋めることはできない。そこで主張そのものを「コード s は述語 P を満たす」として述語で与える（`claim_formal`）。翻訳がないので仮説もなく、r = m だけになる。

```
H := P(s)        m のもとで  H ↔ P(a)
```

P の意味は Γ の定義で決まる。「`Spec.Bounded` とは何か」は Γ に置いた定義そのもので、確率の対象ではなく承認された前提の側に移る。数学で用語の意味を定義が決めるのと同じで、溝は「この定義は意図どおりか」という、定義ごとに一度人が確認する問いに縮む。

事前分布への制約はベイズ認識論の**証言の信頼性モデル**（ボーヴェンス＝ハートマン）のとおり。「情報源が信頼できれば報告は事実と一致し、できなければ報告は事実と無関係に基準率で出る。信頼性と事実は独立」。ここでは F が事実、H が報告、r が信頼できること。

```
μ(g) = γ,  μ(m) = κ                         仮説の基準率
μ(F ∣ g, m の任意の真偽) = π                 事実は仮説と独立
μ(H ∣ どの接続も信頼できない g, m の真偽) = π_H    信頼できないとき、報告は仮説と無関係な基準率の抽選
```

g と m の間の依存は置かない。したがって μ(r) は点ではなくフレシェ区間 [γ + κ − 1, min(γ, κ)] になる。

**m が主張していること。** 「a は s を表す」は、書き下すと次の全称命題で、括弧の中身がすべて m の一部として記録される（`kernel.binding`）。

```
m(s, a, D, call):   すべての x ∈ D について   show(call(x)) = a(x)

s     コード。path::name とファイル内容のハッシュ
a     Lean の項
D     各引数の定義域（名前つき：nat, int, unit, pos, units）と、無作為に引く範囲
call  コードの呼び出し方。前準備の文と、引数 {0}, {1}, … についての式
show  コードの戻り値を書き出す関数。Kernel が持つ（コードの側は関与しない）
```

定義域の値には、Lean 側と Python 側の二つの書き方がある（自然数 3 は両方 `3`、有理数は `(3/4 : ℚ)` と `Fraction(3, 4)`）。出力は書式ではなく値として比べる。定義域の入力でコードが例外を出すことは、全域な a との不一致として扱う。

**対象は任意のファイル、またはその中の箇所。** s は `path` か `path::箇所` で、箇所は Markdown の見出し、JSON のキー、Python の定義名。それ以外の種類のファイルはファイル全体が対象になる。版はその箇所の内容のハッシュ。s は呼び出せるコードである必要はない。その場合 D と call はなく、m は「このハッシュのファイルは a として読める」という主張になる。読みの得方は二つ：エージェントが述べるか、記録した変換式（`kernel.reader`）が計算するか。後者では m は「変換式が正しい」という一つの仮説に縮む。

s・a・D・call のどれかが違えば別の仮説になる。逆に、これらが同じなら誰が述べても同じ m で、同じ入力での検査は同じ証拠になる。これは参照モデルとの突き合わせ（モデルベーステスト）で、関係としては詳細化（a の振る舞いを D の上で s が実現している）にあたる。

m への証拠は Kernel が自分で作る。Leanで a を具体的な入力に適用した値と、実際のコードを同じ入力で走らせた出力を比べる。その扱いは §7 の「全称仮説の検査」。

通信路で言えば、確率 μ(r) で恒等、残りで入力と無関係な出力を返す混合通信路（類比）。

## 6. 知識の同一性 ― 測度代数の距離（一致）

二つの命題の距離を、食い違う世界の確率で定義する。

```
d_μ(A, B) = μ(⟦A⟧ △ ⟦B⟧) = 1 − μ(A ↔ B)
```

これは測度代数のフレシェ＝ニコディム距離（擬距離）。𝒦 上の上限 d̄ = sup_μ d_μ も三角不等式を満たす。すると二種類の同一性は同じ物差しの上に並ぶ。

| | 記号 | 由来 |
|---|------|------|
| 形式的同一性 | d̄(F₁, F₂) = 0 | Lean：[F₁] = [F₂] |
| 接続 | d̄(H, F) ≤ 1 − P̲(r) | ⟦r⟧ ⊆ ⟦H ↔ F⟧ |
| 意味的同一性 | d̄(H₁, H₂) が小さい | 上の二つから導く |

v0.1 §6 は三角不等式そのもの。

```
d̄(H₁, H₂) ≤ d̄(H₁, F₁) + d̄(F₁, F₂) + d̄(F₂, H₂) ≤ (1 − 0.9) + 0 + (1 − 0.8) = 0.3
```

最終原則もこの形で読める。Leanは中央の項を 0 にするが両端の項には触れず、両端の不確実性は中央の 0 を動かさない。

ほかの関係は順序と測度の単調性になる：[F₁] ≤ [F₂] なら μ(F₁) ≤ μ(F₂)、[F₁] ∧ [F₂] = ⊥ なら μ(F₁) + μ(F₂) ≤ 1。

## 7. 証拠 ― 仮想証拠・コピュラ・一般化ベイズ則

**尤度（一致）。** 証拠 e は対象原子 X の真偽だけに依存する尤度を持つ。効くのは比だけなので、パールの**仮想証拠**と同じ。

```
μ′(w) ∝ L_e(w) μ(w)        L_e(w) = a（w ⊨ X）, b（w ⊭ X）
```

**証拠どうしの依存（一致）。** 同じ対象への証拠 e₁,…,e_k の同時尤度は、周辺が決まっていて結合が未知。結合の仕方はコピュラで、どのクラスを許すかを `Kernel(dependence=…)` で選ぶ。

| クラス | 許すコピュラ | P(e₁ ∧ ⋯ ∧ e_k ∣ X) の範囲 | 読み |
|--------|--------------|----------------------------|------|
| `independent` | Π | ∏ aᵢ | 独立 |
| `comonotone` | M | min aᵢ | 同じ証拠を k 回見ただけ |
| `pqd`（既定） | Π ≤ C ≤ M | [∏ aᵢ, min aᵢ] | 正の依存（positive quadrant dependence） |
| `frechet` | W ≤ C ≤ M | [max(0, Σaᵢ − (k−1)), min aᵢ] | 何も知らない（フレシェ＝ヘフディング限界） |

X が真のときと偽のときの結合は別々に選べるので、尤度比は区間になる。v0.1 の「独立を仮定しない」を文字どおりに読むと `frechet`。同一出自の証拠を一つに数えるのは、集合としての冪等性。独立の宣言は、その証拠を Π で結ぶこと。

**全称仮説の検査（一致）。** m は「すべての入力で a とコードが同じ値を返す」という全称命題。m が正しければ、どの入力でも一致は確実である。

```
P(一致 ∣ m) = 1        P(不一致 ∣ m) = 0
```

これは**仮説演繹法**の形で、不一致は反証、一致は確証になる。一致の確率を 1 未満に置くと、検査を重ねるほど「正しいのに全部は一致しない」確率が積み上がり、下界が下がる（3回目の実走で起きた）。

検査が m をどれだけ支持するかは、m が誤りのときに一致する確率で決まる。入力の選び方で二つに分かれる。

| 入力 | 構造 | k 回一致したときの P(全部一致 ∣ ¬m) | 実装 |
|------|------|--------------------------------------|------|
| 人が選ぶ | 依存は未知 | コピュラのクラスの範囲。上限は 1 回ぶんのまま | `check_model` |
| 分布から無作為に引く | **交換可能** | E[qᵏ]。k とともに下がる | `sample_model` |

無作為に引く場合、m が誤りなら「それでも一致する入力の割合」q があり、検査は q のもとで独立になる。q は未知なので検査どうしは独立ではなく交換可能で、これはデ・フィネッティの表現定理の形。q にベータ事前分布（平均 t、集中度 s）を置くと

```
E[qᵏ] = ∏_{i<k} (s·t + i) / (s + i)
```

t = 1/2、s = 2（一様分布）なら 1/(k+1) で、ラプラスの継起則。

事前分布を一つに決めず、平均 t を固定して集中度を s ≥ s_min の範囲で動かす。すると E[qᵏ] は [tᵏ, ∏(s_min·t + i)/(s_min + i)] の区間になる。両端には意味がある。

- s → ∞ は q = t の一点で、検査は独立（コピュラ Π）。
- s → 0 は q が 0 か 1 の二点で、E[qᵏ] = t のまま動かない（コピュラ M）。「誤ったモデルは、無作為な入力では全部一致するか全部外れるか」という事前分布。

つまり s を動かすと正の依存のクラス `pqd` をちょうど一周する。s に下限を置かないかぎり、無作為な検査で下界は上がらない。s_min は「誤ったモデルは、無視できない割合の入力で食い違う」という仮定の強さ。

**不精確ディリクレモデルは使えない。** ウォーリーの不精確ディリクレモデルは s を固定して平均 t を (0, 1) 全体で動かす。この集合では t → 1 が許されるので P(全部一致 ∣ ¬m) の上限が 1 になり、下界は事前のまま動かない。事前の無知に近い集合では潜在変数について学習できない、という既知の限界（ピアッティら）にあたる。

**仕様の仮説 g への証拠（類比）。** 自然言語のまま残る主張では g を直接検査できないので、形式層から読み取れることを証拠にする。どちらも「証明が接続を確率 1 にする」わけではなく、尤度で重みを変えるだけ。

| 観測 | 代数での意味 | 既存概念 |
|------|--------------|----------|
| 反例 o があり Γ ⊢ ¬P(o) | [P] ≠ ⊤（ファイバーの頂点ではない） | 空虚性の検出、仕様のミューテーションテスト |
| 別々の著者が同じ主張を同じ仕様の類に結んだ | [P₁] = [P₂] | N バージョン、評価者間一致 |

反例がいくつあっても事実は「⊤ ではない」の一つなので、証拠は 1 件ぶん。捕まえられるのは弱すぎる述語だけで、強すぎる述語や別の性質を言っている述語は見逃す。著者どうしは同じ誤読をしやすいので、一致は依存する証拠として扱う。

**更新（一致）。** 分布の集合を要素ごとに条件づける。ウォーリーの**一般化ベイズ則**。

```
𝒦∣E = { μ(· ∣ E) : μ ∈ 𝒦 }
```

比の最適化なので線形分数計画になり、チャーンズ＝クーパー変換で線形計画に落とす（実装は Σ L·y = 1 の正規化行）。

**区間の拡大（一致）。** 条件づけで区間が広がる現象は**ダイレーション**（サイデンフェルド＝ワッサーマン）として知られている。最初の実走で下界が 0.905 から 0.890 に下がったのはこれ。`pqd` や `frechet` では、依存する証拠を足すと下界が少し下がることもある。

## 8. 状態 ― 結び半束（類比）

状態はイベントの集合 S で決まり、推論は S の関数。

```
infer : 𝒫(Events) → 区間        merge(S₁, S₂) = S₁ ∪ S₂
```

証明の追加は制約の共通部分、証拠の更新は尤度の積なので、どちらも可換で、重複は冪等。つまり状態は結び半束で、エージェント間の知識共有は結び（CRDT でいう grow-only set）。

ただし確率は S について単調ではない（証拠は上げも下げもする）。単調なのは Ω の縮小だけ。また `ground` は `claim` の後、という因果順序は必要。

## 9. 置いている仮定

1. **接続の意味** ⟦g ∧ m⟧ ⊆ ⟦H ↔ F⟧。形式的な主張では ⟦m⟧ ⊆ ⟦H ↔ F⟧。
2. **信頼性モデル** 事実は仮説と独立。信頼できない接続のもとでは、主張は仮説と無関係に基準率で決まる。
3. **証拠の局所性** e は対象原子を通じてのみ世界に依存する（マルコフ条件）。
   全称仮説の検査では、誤ったモデルの一致率 q に平均 t・集中度 s_min 以上のベータ事前分布を置く。
4. **証拠の依存のクラス** 既定は正の依存（`pqd`）。`frechet` を選べばこの仮定は外れる。
5. **成分間の無関連性** 連結でない成分は互いの区間を動かさない（ウォーリーの epistemic irrelevance）。Leanが真偽を決めた F は定数で、成分をつながない。

1 は定義、2〜5 はモデルの選択で、v0.1 にはなかったもの。

## 10. 対応が崩れている所

**F の基準率。** 生成元 F に基準率 π を置くのは信頼性モデルの側の都合で、代数の側に根拠はない。`implies` などの関係に現れた F からは基準率を外している（置くと含意が同値に化ける）。関係のある生成元にどう事前分布を置くかは、既存概念に対応させられていない。

**形式的な主張は、溝を消したのではなく移した。** 「定義が意図どおりか」は Γ を承認する人の判断になり、このシステムの確率には現れない。定義が意図とずれていれば、下界がいくら高くても意味がない。

**仮説どうしの依存。** g と m、あるいは別の主張の g どうしの依存は未知のままにしている。同じエージェントが同じ呼び出しで書いたものなので正に依存していそうだが、証拠の場合と違ってコピュラのクラスを当てていない。

**コードから a を得る手順はない。** m の中身は明示したが、a はいまも誰かが書く。同じコードに複数の a が書かれうるし、f を呼ぶ g のモデルは f のモデルから組み立てられない（合成を保たない）。入口の推測そのものをなくすには、言語の一部に翻訳規則を決めるか、コードを Lean で書くことになる。

**版の単位はファイル 1 つ。** s のハッシュは 1 ファイルの内容で、そのコードが呼ぶ別ファイルの変更は見えない。

**m の意味が検査の仕方で変わる。** 証明に使うときの m は「すべての入力で一致」だが、無作為な検査が支持するのは「この入力分布のもとでほぼ確実に一致」まで。分布の下で確率 0 に近い入力でだけ食い違うモデルは、いくら引いても見つからない。人が選ぶ境界値の検査はそこを補うが、支持としては 1 回ぶんにしかならない。

**確率 0 は戻らない。** 不一致 1 件で m は確率 0 になり、以後どんな証拠でも動かない。検査の仕組みの側の誤り（出力形式の違いなど）に備えて、証拠の撤回（`retract`）を理由つきのイベントとして用意したが、これは意味論の外の操作。

**対象の等しさは全域。** `obj_eq` は a₁ = a₂ を要求する。「lo ≤ hi の範囲では同じ」は言えない。定義域つきの等しさ（部分同値関係、セトイド）が要る。

**ハイティングかブールか。** `Classical.choice` を許すので 𝓛_Γ はブール代数。許さなければハイティング代数で、世界は 2 値の付値ではなくクリプキ模型になり、確率層を作り直すことになる。

**Γ が動く場合。** Γ ⊆ Γ′ なら 𝓛_Γ ↠ 𝓛_Γ′ で古い関係は保たれる。Γ を縮めたり定義を変えたりした場合は対応が切れ、Π は無効になる。
