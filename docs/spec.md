# 確率的知識とLeanによる形式的同一性の意味論

設計仕様 v0.2 — 実装に合わせた叩き台

v0.1 の原則はそのまま残す。

> 知識からLean命題への接続は仮説であり、Lean命題間の証明された関係は確定的である。
> 証明の確実性は接続の不確実性を消去せず、接続の不確実性は証明の確実性を損なわない。

変えたのは「どう計算するか」と「数値をどこから持ってくるか」。変更点はすべて §2 に理由つきで並べた。

## 2. v0.1 からの変更

| # | v0.1 | v0.2 | 理由 |
|---|------|------|------|
| 1 | 結合分布 μ を保持する | 分布は持たない。`infer` は区間 `[lo, hi]` を返す | Ω は命題数に対して指数的。述べられていない依存は「未知」のまま残し、幅として見せる |
| 2 | `ground(H, F, prior)`、`observe(e, likelihood)` | 事前確率と尤度はカタログから引く。エージェントは数値を渡せない | エージェントが数値を言えば、それは主観的確信度の保存になる |
| 3 | 証明は F₁ ↔ F₂ のみ | `holds` / `not` / `iff` / `implies` / `contradiction` | 並列作業では衝突（矛盾）の検出が同値性と同じくらい要る |
| 4 | 証明の追加も確率状態の変化 | 証明は Ω の絞り込み。ベイズ更新ではない | Leanの定理は「最初から不可能だった世界」を消す。経験的証拠と同じ更新にすると事前確率と衝突する |
| 5 | 証拠の依存は結合確率で表す | 同一出自は同一証拠。それ以外は「完全重複〜独立」の区間。独立は理由つきで宣言する | 任意の依存（フレシェ）を許すと、証拠が増えるほど下界が下がる |
| 6 | 証拠はエージェントが報告 | テスト等は Kernel が自分で実行して記録する | 自己申告は証拠の出自を曖昧にする |
| 7 | 状態変化は2種類 | 3種類：モデル拡張 / 証拠 / 証明 | `ground` と独立性宣言はどちらでもない |

## 3. モデル

原子命題は3種類。

- **H** 知識命題。同じ文面は同じH。
- **F** Lean命題。`iff` が証明されたFは一つの同値類にまとめ、以後は一つの原子として扱う（形式的同一性）。
- **G** 接続仮説。意味は `G → (H ↔ F)`。

可能世界は、質問に現れる原子とそこから接続・証明でつながる原子（連結成分）の真偽割り当て。Leanの定理に反する世界は最初から除く。

事前分布は次の線形制約を満たす分布すべて。一つに決めない。

- `P(G) = π_G`
- `P(H | Hの接続がどれも成立しない) = π_H`
- 同値性以外の証明に現れないFについて `P(F) = π_F`、および各接続について `P(F | G) = π_F`

最後の条件は「形式化が正しいかどうかと、その形式命題が真かどうかは無関係」という仮定で、これがないと `ground` しただけでHの確率が広がる。

証拠は対象原子の真偽だけに依存する尤度 `[P(e|真), P(e|偽)]` を持つ。同じ対象への証拠は、独立が宣言されない限り一つのブロックに入り、ブロックの尤度は「全部が同じ証拠の重複」と「全部が独立」の両端をとる。

`infer(φ)` は、上の制約と両端の尤度のもとで `P(φ | 証拠)` の最小と最大を線形計画で解く。

### 数値例（テスト済み）

| 状況 | 結果 |
|------|------|
| π_G₁=0.9, π_G₂=0.8, `F₁ ↔ F₂` を証明 | `P(G₁∧G₂) ∈ [0.7, 0.8]`、`P(H₁↔H₂) ∈ [0.7, 1]`（v0.1 §6） |
| π_G=0.9, π_H=0.5, `F` を証明 | `P(H) = 0.95`、`P(G) = 0.9` のまま（条件3） |
| 尤度 0.9/0.15 の証拠を別々の実行で2件 | `P(H) ∈ [0.857, 0.973]`。独立を宣言すると 0.973 |
| 同じ実行を2体が報告 | 1件として扱う。変化なし |
| 同じHへの2つの形式化が Lean上で矛盾 | `Conflict` を返す |

## 4. 操作（MCPツール）

| ツール | 内容 |
|--------|------|
| `claim(text)` | Hを登録 |
| `ground(h, lean)` | GとFを導入 |
| `observe_command(target, kind, command)` | Kernelがコマンドを実行し、成否を証拠として記録。出自は「コマンド＋作業ツリーの状態」 |
| `observe(target, kind, outcome, source)` | コマンドで作れない証拠（レビュー、逆翻訳、具体例の突き合わせ） |
| `declare_independent(eid, justification)` | 証拠を独立として扱う宣言 |
| `prove(relation, fs, proof)` | Lean Gateに証明を提出。失敗は証拠にしない |
| `infer(query)` | 原子の論理式に対する `[lo, hi]` |
| `status()` | 全主張の区間、同値類、受理済み証明 |

## 5. Lean Gate

- 定理の文面はGateが登録済みのF文面から書く。エージェントが渡すのはタクティクだけ。
- 受理条件：Leanがエラーなく通り、`#print axioms` の結果が許可リスト（`propext`、`Classical.choice`、`Quot.sound`）に収まる。
- Γ ＝ ツールチェーン＋`lean/Gamma.lean`＋許可リスト。証明イベントにΓのハッシュを記録する。

## 6. 正しさの条件（v0.1 §9 との対応）

1. 意味論の統一 — H・F・Gは同じ世界の上の原子。事実と仮説の区別はない。
2. 証明の健全性 — 証明イベントはGate経由でしか書けない。
3. 接続の不確実性 — 証明はGの確率を変えない（テスト済み）。
4. 依存性の保存 — 同一出自は重複排除、それ以外は宣言まで区間。
5. 確率的整合性 — 区間は制約を満たす分布全体の上の最小と最大。

## 7. 未解決

- **カタログの数値は仮置き。** 較正データがまだない。ここが実質的に系全体の信頼性を決める。
- **証拠が接続を通じて他の原子の区間を広げる。** G同士の事前の相関が未知なので、G₁への証拠がG₂の下界を少し下げることがある（dilation）。
- **`implies` / `contradiction` に現れるFには事前確率を置いていない。** 置くと含意が同値に化けるため。その分、区間が広い。
- **基準率と証明が両立しないとき `Conflict` で止まる。** 事前確率を緩める規則が要るかもしれない。
- **Gateの入力検査は禁止語リスト。** マクロ等による文面の書き換えを原理的には防げていない。
- **連結成分が14原子を超えると解けない。** 分割か近似が要る。
- **コードそのものはLeanの外にある。** Fはコードのモデルに関する命題で、不確実性の大半はGに残る。
- **Γが変わったとき、古い証明をどう扱うか未定義。**
