# 散文についての決定

実行:

```
python -m experiments.prose.run OUT_DIR read       # 互いに見えない 3 体が同じ箇所を読む
python -m experiments.prose.run OUT_DIR maintain   # 文書とコードを書き換えて、決定に当てる
```

生の結果は `results/read.json` と `results/maintain.json`。

## 設定

対象は `docs/spec.md`（日本語の散文と表）。決定は 5 つの事実で、文書の該当する節がそれを言っていること、同じ事実をコードが持つ場合はコードもそうなっていることを求める。

| 事実 | 文書の箇所 | 型 | コードの箇所 |
|------|------------|----|--------------|
| 許可される公理 | `5. Lean Gate` | 文字列のリスト | `pw/lean_gate.py::ALLOWED_AXIOMS` |
| 解ける連結成分の上限 | `7. 未解決` | 自然数 | `pw/kernel.py::Kernel.__init__` |
| MCP ツールの名前 | `4. 操作（MCPツール）` | 文字列のリスト | `pw/mcp_server.py` |
| 当て直しが報告する状態 | `9. 時間をまたぐ決定` | 文字列のリスト | — |
| 既定の依存クラス | `3. モデル` | 文字列 | `pw/kernel.py::Kernel.__init__` |

文書の側はエージェントが読んで項を述べる。コードの側は変換式（正規表現で抜き出す式）が計算する。対象は節・定義の単位で、その内容のハッシュで版を決める。

## 読みの安定性

互いに見えない 3 体（claude-opus-5-5）が、同じ 5 箇所を読んだ。各 15 手、$0.27、約 25 秒。

**15 個の読みはすべて同じ値で、15 個とも決定の成立を証明した。** 違いは 1 体が `14` を `(14 : Nat)` と書いたことだけ。状態の一覧は日本語の語（現行・再確立・違反・証明の対象外・失効・裏付けなし）を英語の識別子に訳す必要があったが、3 体とも同じ対応を選んだ。

読みに解釈が入った箇所は、ワーカー自身が報告している。

- 文書は「14 原子を超えると解けない」と言っているだけで、「解ける上限が 14」はそこからの読み取り。
- 公理は文書に並び順がなく、決定が求める「アルファベット順」は読み手が並べ替えた結果。

## 維持

1 体目の読みを土台に、人が読みを確認したうえで、書き換えを順に当てた。

| 書き換え | `pw.check` | そのあと |
|----------|-----------|----------|
| 決定と無関係な節に 1 文足す | 全部「現行」、終了コード 0 | — |
| 公理の節を言い換える（順序も変える） | その決定だけ「失効」 | 読み直し（6 手、$0.18）で同じ項、決定は成立。ただし 0.875 で閾値に届かない |
| 上限を 16 に、既定を `frechet` に変える | その 2 つだけ「失効」 | 読み直し（8 手、$0.22）で 2 つとも「違反」（Lean が否定を受理） |
| コードの許可リストに公理を 1 つ足す | コード側の決定が「違反」（エージェントなし） | — |

- **節の単位で判定しているので、無関係な編集では何も起きない。** 5 つの決定は同じファイルの別々の節にあり、書き換えた節の決定だけが失効した。
- **言い換えには読み直しが要るが、結論は変わらない。** 読み直した項は元と同じ値だった。
- **意味の変更は違反として出る。** エージェントは変わった値を読み、決定の否定を証明した。
- **コードの側は、エージェントなしで違反と出る。**
- 読み直したエージェントは、頼まれていない矛盾も報告した：§3 の既定値を変えたのに §2 の表は元のまま、という文書内の食い違い。これは報告の文章にあるだけで、Kernel には記録されない。

## 人の確認が要る場面

エージェントが述べただけの読みは 0.875 で、既定の閾値 0.9 に届かない。人が読みを確認すると 0.984 になる。節が変わって読み直すと、確認の効果は残らず 0.875 に戻る（言い換えのあとの状態がそれ）。

つまり散文の対象では、**変更のたびに人の確認が 1 回要る**。確認の中身は「この節は、この値を言っているか」で、節と値を見比べるだけ。カタログの試行ではエージェントがファイルへの検査を自分で足して閾値を超えたが、今回は誰も足さなかった。

## この実行で見つかって直したこと

1 回目の実行は準備の段階で止まった。どちらも Gate の不具合で、直してから流し直した。

- **入力検査が文字列の中身に反応した。** ツール名 `"declare_independent"` が禁止語 `declare_` に当たった。文字列リテラルの中身は検査しないようにした（バックスラッシュを含む入力は従来どおり全体を検査し、引用符を文字リテラルで書いた入力は拒否する）。
- **自明に成り立つ命題が証明できなかった。** リストどうしの等式は Gate の前処理だけで証明が終わり、そのあとのタクティクが「解くゴールがない」で失敗していた。前処理で終わった場合は受理する。

## 限界

- **読ませたのは事実の抜き出しだけ。** 名前の一覧、数値、既定値。規範や条件を述べる散文（「〜すべき」「〜の場合は」）は試していない。自然言語の調査（`docs/natural-language.md` §3）で見た損失は、問いと型を人が決めたこの形では出なかったが、型に収まらない内容では出るはず。
- **決定の側が答えを知っている。** 述語は「このリストに等しい」という形で、正解が決定の中に書いてある。エージェントがそれに引きずられて読んだ可能性は排除できていない（意味を変えた編集では引きずられずに否定を証明したので、少なくとも明白な食い違いは読めている）。
- **3 体は同じモデル。各 1 回の実行。**
- **節の中の、決定に関係しない文の編集でも失効する。** 単位は節までで、文までは絞っていない。
