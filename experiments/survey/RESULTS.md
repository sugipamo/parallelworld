# 何が複数箇所に書かれていて、何が乗らないか：2 つのリポジトリ

対象: `theskumar/python-dotenv`（Python、コミット `4fbc6ff`）と `joho/godotenv`（Go、コミット `97a2850`）。どちらも小さく、長く保守されていて、README がコマンドや挙動を説明している。読み取りでクローンし、宣言と記録はクローンの中だけに書いた。相手には何も送っていない。対象のコードは実行していない。

宣言は `results/*-facts.json`、チェックの出力は `results/*-check.txt`。

## 問い

miclow（`experiments/external/RESULTS.md`）では、いちばん実害のありそうな食い違いが書式についてのもので、宣言できなかった。そこから 2 つの案が出た。

1. 書式や振る舞いを確かめる仕組み（対象のコードを動かす）を足すか。
2. 正規表現より広い「変換器」（箇所の本文を値に変える、決まった形の実行可能な部品）を足すか。

どちらも 1 つのリポジトリの 1 件が根拠だった。作る前に、ほかのリポジトリで、複数箇所に書かれている事柄がどういう種類のものかを数えた。

## やったこと

1. 先に手で README・設定・コードを読み、複数箇所に書かれている事柄を種類別に書き出した。
2. `pw.discover --apply`（何も宣言していない状態から）。
3. 探索が挙げなかったもののうち宣言できるものを、手で名前を付けて足した（python-dotenv に 2 つ、godotenv に 2 つ）。
4. `pw.maintain` で読ませ、`pw.check` で一致を見た。読み手の測定はしていない（知りたいのは一致するかどうかと、宣言できるかどうかなので）。

費用は合計 $1.40。

## 結果

**宣言した 14 の事実（31 箇所、うち 5 つは一部を挙げる箇所）は、すべて一致していた。** 食い違いは見つからなかった。

| | python-dotenv | godotenv |
|---|---|---|
| 探索が自力で挙げた事実 | 7（14 箇所） | 3（8 箇所） |
| 手で名前を付けて足した事実 | 2 | 2 |
| 食い違い | 0 | 0 |
| 目隠しの読み手が断った箇所 | 0 | 0 |

- 探索は、手で見落としたものを見つけた（`.bumpversion.cfg` の版、ワークフロー間で揃えてある `actions/checkout` の固定）。逆に、CLI のサブコマンド、`--format` の選択肢、公開関数、モジュールのパスは挙げなかった。
- godotenv では、探索役が自分から README の節を「一部を挙げる箇所」として出した（フラグ 3 つのうち 2 つ）。手で足した 3 つの包含（サブコマンド、`--format`、公開関数）も成り立った。
- python-dotenv は、文書のコピー（`docs/index.md` など）をシンボリックリンクにしていて、重複そのものがない。

## 種類別に数えると

手で書き出した「複数箇所に書かれている事柄」を、いまの形に乗るかどうかで分けた。

| 種類 | python-dotenv | godotenv | 例 |
|------|---|---|---|
| 値・一覧が等しい（正規表現で読める） | 6 | 3 | 版、環境変数名、既定値、フラグ、既定のファイル名、モジュールのパス |
| 一覧に含まれる（一部を挙げる箇所） | 2 | 2 | README の例が使うサブコマンド・関数は、コードにあるものの一部 |
| 値としては同じだが、コード側が正規表現で読めない | 4 | 0 | 下の表 |
| 関係が「等しい」「含まれる」でない | 1 | 1 | 対応する版の最小値。Go の版が 3 箇所で 3 つの数字 |
| 振る舞い・書式についての記述 | 9 ほど | 6 ほど | 変数展開の優先順位、空白や引用符の扱い、例の入力と結果、有効な `.env` の例 |

### 正規表現で読めなかったもの（python-dotenv）

| 事柄 | コード側の書き方 | なぜ読めないか |
|------|------------------|----------------|
| tox が試す Python の版 | `envlist = lint,py{310,311,…}` | ほかの箇所は `3.10`。取り出した文字列を別の表記に直す必要がある |
| CLI のサブコマンド | `@cli.command(name="list")` と、名前なしの `@cli.command()` の下の `def get` | 名前の出どころが 2 通りで、グループ 1 つの正規表現では拾えない |
| `--format` の選択肢 | `click.Choice([...])` が同じファイルに 2 つある | 「`--format` の近くの一覧」という範囲の指定と、取り出した文字列を項目に分ける操作が要る |
| エスケープ文字 | 正規表現の文字クラス `[\\'\"abfnrtv]` | 文字クラスを項目の一覧に展開する必要がある |

- サブコマンドと `--format` は、コード側を**ファイル全体をエージェントに読ませる箇所**として宣言して通した。動くが、そのファイルが変わるたびにエージェントの読み直しになる。
- tox については、探索役は `envlist` を避け、同じファイルの中で表記が合う別の行（版ごとの mypy の呼び出し）にパターンを当てた。提案は検査を通り、値も合っているが、**tox が実際に試す版の一覧は宣言されていない**。そこがずれても何も言われない。
- 最小の版は、探索役が「CI の版の一覧の先頭の要素」を正規表現で取り出して `requires-python` と比べる形にした。一覧の並びに頼っている。
- godotenv の Go の版は、`go.mod` が 1.13、CI が試すのは 1.22 以上、README が言うのは 1.24 以上（ある機能を使う場合）。3 つは別の事柄で、互いの関係（CI が試す最小の版は `go.mod` 以上のはず、など）は言えない。`go.mod` の版を CI が試していないことは、食い違いと言えるかもしれないが、判断は持ち主のもの。

### 振る舞い・書式についての記述

README の分量の半分以上がこれにあたる。数でも、宣言できた事実（14）と同じくらいある（15 ほど）。

- python-dotenv:「`$DOMAIN` のような波括弧なしの変数は展開しない」「値のない `FOO` は `None` になる」「次の 2 つの例は同じ意味」など。
- godotenv:「次は有効な env ファイル」「既存の環境変数が優先される」「`-f` を省くと `.env` を読む」など。

これらが実際に成り立っているかは確かめていない（対象のコードを動かしていないので）。どちらのプロジェクトにも自前のテストがあり、godotenv は README の例に近い形の fixture を持っている。

## 2 つの案について言えること

**変換器（案 2）: 必要な場面は実際にあった。ただし、要るのは実行可能な部品ではなく、パターンの小さな拡張で足りる。**

読めなかった 4 件のうち 3 件は、次の 3 つの操作があれば宣言のまま読める。どれも何も実行しない。

| 操作 | 使う場面 |
|------|---------|
| 範囲を絞ってから探す（先に 1 か所を特定し、その中で `find_all`） | `--format` の近くの `Choice` |
| 取り出した文字列を項目に分ける | `"simple", "json", "shell", "export"` を 4 つに |
| 取り出した文字列を書き換える（`py(\d)(\d+)` → `\1.\2`） | `py310` を `3.10` に |

サブコマンド（名前の出どころが 2 通り）と文字クラスの展開は、これでも読めない。構文木を見る変換器が要るのは、この 2 件。件数としては 1 つのリポジトリで 2 件。

**書式・振る舞いの確認（案 1）: 記述の量は多いが、食い違いの証拠は増えなかった。**

README が述べていることの半分は振る舞いで、この仕組みはそこを見ていない。それは確かめられた。一方、その記述が実際にずれている例は、今回の 2 つでは見つけていない（確かめる手段を持っていないので、「見つからなかった」ではなく「見ていない」）。観測された書式の食い違いは、依然として miclow の 1 件だけ。

## その後：パターンに範囲と書き換えを足した

上の表の 2 つの操作を、パターンに足した（分割は、範囲を絞ってから `find_all` すれば足りるので入れていない）。どちらも宣言のままで、何も実行しない。

| キー | 意味 |
|------|------|
| `within` | ちょうど 1 回一致する正規表現（グループ 1 つ）。`find`・`find_all` はそのグループの中だけを探す |
| `rewrite` | `[パターン, 置き換え]`。取り出した各片に全体として一致させ、`\1`〜`\9` で組み直す |

python-dotenv のクローンで、読めなかった 2 件を宣言し直した。

```json
{"at": "tox.ini", "read": {"within": "^envlist = .*py\\{([^}]+)\\}", "find_all": "(\\d+)(?:,|$)",
                           "rewrite": ["(\\d)(\\d+)", "\\1.\\2"], "sort": true}}
{"at": "src/dotenv/cli.py", "read": {"within": "\"--format\",[\\s\\S]*?click\\.Choice\\(\\[([^\\]]+)\\]",
                                     "find_all": "\"(\\w+)\"", "sort": true}}
```

- tox が試す版の一覧（`py{310,…}`）が、`3.10`〜`3.15` として読め、`pyproject.toml` と一致した。探索役が代わりに当てていた mypy の行は外した。写しの `envlist` に `39` を足すと、食い違いとして報告された。以前の宣言では、この変更は何も言われなかった。
- `--format` の選択肢は、エージェントがファイル全体を読む箇所から、パターンで読む箇所になった。`cli.py` が変わっても、エージェントの読み直しは要らない。
- 探索役への指示にも、この 2 つのキーと「表記が違っても、本当にその事柄を決めている箇所を読むこと。たまたま同じ表記の別の行で済ませないこと」を足した。探索役がこれを使うかは、まだ走らせていない。

**読めないままのもの。**

- CLI のサブコマンド（名前がデコレータの引数か、なければ関数名）。
- miclow の構造体のフィールド（属性で名前が変わるものと、除外されるものがある）。範囲は絞れるが、絞った中で同じ問題が残る。
- 正規表現の文字クラスの中身。

この 3 件は構文を見る読み方が要る。3 つのリポジトリで 3 件。

**途中で見つけた不具合。** 1 つの事実に同じ箇所を 2 回（別々の読み方で）書くと、エラーにならず、2 つ目の読み方が黙って無視されていた。上の tox の宣言を足したときに、古いパターンが残っていて気づいた。同じ箇所を 2 回書くとエラーになるようにした。同じファイルの中の 2 つの記述を両方挙げたい場合は、箇所の名前で分けられなければ宣言できない。

## 限界

- リポジトリ 2 つ。どちらも小さく、保守が行き届いている。選んだのは開発中のエージェント。
- 種類の分類と件数は、手で（同じエージェントが）数えた。「ほど」と書いた数は、文をどこで区切るかで変わる。
- 食い違いが 0 だったのは、宣言した 14 の事実についてだけ。
- 読み手を測っていないので、規則の上ではどの読みも「成り立つ」とは言えない状態で一致を見ている。
